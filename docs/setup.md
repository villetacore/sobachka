# Установка и первая настройка

## Запуск

Нужны Docker и Docker Compose. Ресурсы скромные: ~1 ГБ RAM, ~2 ГБ на диске (основное — образ PyTorch CPU).

```bash
cp .env.example .env
# заполните ADMIN_USERNAME, ADMIN_PASSWORD, APP_SECRET_KEY, PUBLIC_URL и POSTGRES_PASSWORD
docker compose up -d --build
```

- Поставьте перед `web` обратный прокси с HTTPS (Caddy или nginx + certbot), укажите внешний адрес в `PUBLIC_URL` **без завершающего слеша**. На хостинге `COOKIE_SECURE=true`.
- Войдите по `ADMIN_USERNAME` / `ADMIN_PASSWORD`. При пустой таблице пользователей создаётся первый администратор; открытой регистрации нет. Пароль: 12–72 байта UTF-8 (для латиницы это 12–72 символа).
- `APP_SECRET_KEY` — 32 случайных байта в base64 (`openssl rand -base64 32`). Сделайте резервную копию ключа отдельно от базы: он шифрует токен бота.
- В «Пользователях» создайте личные учётные записи. После первого запуска можно удалить `ADMIN_PASSWORD` из окружения: повторный запуск существующего администратора не меняет.
- В «Настройки и ИИ» вставьте токен от @BotFather и нажмите «Проверить и сохранить бота». Имя и @username определяются через Telegram. Бот применяется без перезапуска. Нужен отдельный бот без webhook и другого процесса polling.
- Каждый пользователь открывает «Мой аккаунт и Telegram» → «Подключить Telegram», переходит по одноразовой ссылке и нажимает Start. Затем «Обновить статус», выбирает направления, включает уведомления и сохраняет подписки. Тест отправляется только ему.

## Роли и доступ

| Роль | Доступ |
|---|---|
| Администратор | Все функции, пользователи, источники, общие настройки и бот |
| Оператор | Заказы, оценки, отклики, общие профили и личные уведомления |
| Наблюдатель | Просмотр заказов и личные уведомления; без изменения общих данных |

Заказы, профили, оценки и обучение общие для команды. Это одна командная установка, не изолированные рабочие пространства. Уведомления персональные: все направления (включая будущие) либо выбранные профили. Фильтр подписок применяется к **лучшему профилю** заказа. Пустой выбор при выключенном «Все направления» не отправляет ничего. Общий переключатель уведомлений администратора действует на всех; ручная отправка и тест адресованы только текущему пользователю.

Пароли хранятся как bcrypt-хеши, сессии — как хеши случайных секретов в БД, сроком 12 часов. Cookie: HttpOnly, SameSite=Strict и Secure по умолчанию. Выход отзывает сессию; смена пароля, роли и блокировка отзывают все сессии пользователя. Нельзя отключить или понизить последнего активного администратора. API проверяет роли, Origin и защитный заголовок на изменяющих запросах. Подбор пароля ограничен: 10 попыток для одного логина и 100 суммарно за 15 минут; смена своего пароля также ограничена.

Привязка Telegram действует 10 минут, одноразовая, новая ссылка отменяет старую. Передавать ссылку другому человеку нельзя. Разрешены только личные чаты; один Telegram нельзя привязать двум учётным записям. Отключение привязки прекращает уведомления и отменяет ссылку. Блокировка пользователя запрещает и действия в боте. При замене бота на **другого** или его отключении все привязки, подписка на отправку и ссылки сбрасываются; смена токена того же бота сохраняет их. Токен в базе зашифрован AES-GCM и не возвращается через API. Старый глобальный `TELEGRAM_CHAT_ID` больше не используется.

Для локальной разработки по HTTP: `PUBLIC_URL=http://localhost:5173`, `COOKIE_SECURE=false`; для локального Docker — `PUBLIC_URL=http://localhost:8088`. Сервер должен получать тот же внешний Origin, который открывает браузер. PostgreSQL и ML не публикуйте наружу; Compose открывает только web. Запускайте один экземпляр backend (Telegram long polling и очередь рассчитаны на него).

## Первая настройка

1. **Источники.** Площадок по умолчанию нет. Добавьте их в разделе «Источники»: RSS-ленты, страницы со списком
   заказов или JSON API. Если площадки нужны многим установкам, опишите их один раз в `config/presets.json` —
   они появятся под кнопкой «Готовые площадки» ([подробнее](sources.md)).
2. **Профили.** В новой установке есть один профиль-пример. Переименуйте его под своё направление или создайте свои:
   ключевые слова, минус-слова, шаблон отклика. Впишите в поле «Опыт» реальные факты о себе: оборудование, годы,
   примеры работ, ссылку на портфолио. Это подставляется в отклик.
3. **Песочница** внизу профиля: вставьте пару реальных заказов и посмотрите процент и текст отклика.
4. **Порог** по умолчанию 60%: одно слово в заголовке или два в описании дают уведомление, одно слово в описании — нет.
5. **Минус-слова** по умолчанию отсекают учебные заказы («курсов», «дипломн», «реферат», «контрольн работ»).
   Уберите лишнее, если берёте такие заказы.
6. Нейросеть дообучается сама на новых заказах, ничего делать не нужно. Если хотите, отмечайте заказы 👍/👎:
   каждая оценка весит как три примера авторазметки, и сеть быстрее подстроится под ваши предпочтения.

При первом опросе источника заказы сохраняются **без** уведомлений, чтобы бот не завалил вас старыми заказами.

## Шаблон отклика

Подстановки: `{title}` — название заказа, `{matched}` — найденные в заказе слова, `{direction}` — название профиля,
`{experience}` — поле «Опыт», `{budget}` — бюджет. Варианты разделяются строкой `---`.

Хороший первый отклик: начать с задачи клиента, а не с себя; коротко сказать, как будете делать;
опереться на реальный опыт; закончить одним простым вопросом, на который легко ответить.

## Обновление существующей установки

1. Сделайте резервную копию PostgreSQL. Новые таблицы добавляются автоматически, существующие заказы, профили и источники сохраняются.
2. Добавьте новые переменные из `.env.example`. `ADMIN_TOKEN` больше не даёт доступ. **Сохраните прежний `POSTGRES_PASSWORD` для существующего тома**: изменение `.env` не меняет пароль уже созданной БД.
3. Пересоберите контейнеры и войдите первым администратором. Если `TELEGRAM_BOT_TOKEN` уже задан, он импортируется в зашифрованные настройки при первом запуске; далее настройки из БД приоритетнее окружения. После импорта токен можно удалить из `.env`.
4. Подключите Telegram заново для каждого пользователя и включите личные подписки. Старая отправка в общий chat_id прекращается.
