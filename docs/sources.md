# Источники заказов

Источники настраиваются в веб-интерфейсе, в разделе «Источники». В код не зашита ни одна конкретная площадка:
всё, чем сайты отличаются друг от друга, описывается в настройках источника. Поэтому подключить можно любую
биржу или доску заказов, у которой есть RSS-лента, HTML-страница со списком или JSON API.

При первом опросе источника заказы сохраняются **без** уведомлений, чтобы бот не завалил вас старыми заказами.
Первым опрос считается, пока от источника не пришло ни одного заказа.

## Типы источников

| Тип | Что читает | Что указать |
|---|---|---|
| `rss` | RSS 2.0 и Atom. Полный текст берётся из `content:encoded`, если он длиннее `description` | адрес ленты |
| `html` | ссылки со страницы-списка, отфильтрованные регулярным выражением. Описание и бюджет подгружаются со страницы заказа | адрес списка и шаблон ссылок, при необходимости настройки |
| `json` | JSON API, из которого сайт сам берёт заказы | адрес API и настройки |

Если в `rss`-источник вставить обычную страницу сайта, опрос завершится ошибкой с подсказкой выбрать тип `html`.

## Настройки разбора

Для типов `html` и `json` в форме источника есть поле «Настройки разбора» — JSON-объект. Для `rss` оно не нужно,
для `html` необязательно.

### `json`

```json
{
  "method": "POST",
  "form": { "category": "all" },
  "headers": { "X-Requested-With": "XMLHttpRequest" },
  "page_param": "page",
  "pages": 3,
  "items": "data.orders|orders",
  "filter": { "status": "open" },
  "fields": {
    "id": "id",
    "title": "title",
    "description": "description",
    "url": "https://example.net/orders/{id}",
    "category": "{type} / {tags}",
    "budget": "price",
    "budget_min": "budget.min",
    "budget_max": "budget.max",
    "currency": "budget.currency",
    "published": "created_at",
    "time_format": "2006-01-02 15:04:05",
    "timezone": "+03:00"
  }
}
```

| Ключ | Что значит |
|---|---|
| `method` | `GET` (по умолчанию) или `POST`. Для `POST` поля `form` уходят телом `x-www-form-urlencoded` |
| `headers` | дополнительные заголовки запроса |
| `page_param`, `pages` | имя параметра страницы и сколько страниц читать (до 20). Чтение останавливается на пустой странице |
| `items` | путь к массиву заказов в ответе. Варианты через `\|` — берётся первый найденный |
| `filter` | оставлять только заказы, у которых поле равно значению |
| `fields` | где в заказе нужные поля. Значение — путь (`budget.max`, `tags.0`) или шаблон с подстановками (`/orders/{id}`). Относительные ссылки дополняются адресом API. Списки склеиваются через запятую |

Обязательны `items`, `fields.title` и `fields.url`. Без `fields.id` заказ узнаётся по ссылке.
`currency` — путь к полю или сама валюта (`"₽"`). Дата без `time_format` разбирается как RFC 3339 или
`2006-01-02 15:04:05`. Формат задаётся в нотации Go: `02.01.2006` — это «день.месяц.год».

Чтобы найти API площадки, откройте в браузере инструменты разработчика, вкладку «Сеть» (Network), отфильтруйте
запросы по Fetch/XHR и обновите страницу со списком заказов. Запрос, который возвращает список, и есть адрес API.

### `html`

Без настроек тип `html` берёт со страницы все ссылки, подходящие под шаблон, а текст ссылки становится заголовком.
Если на странице вперемешку заказы и что-то ещё (реклама исполнителей, объявления о продаже), включите режим карточек:

```json
{
  "card": "<div class=\"card ",
  "include": "class=\"card-type\">Заказ",
  "details_from": "Описание",
  "details_to": "Вложения",
  "fields": {
    "title": "<h2[^>]*><a[^>]*>(.*?)</a>",
    "published": "от (\\d{2}\\.\\d{2}\\.\\d{4})",
    "time_format": "02.01.2006",
    "category": "class=\"card-type\">([^<]*)"
  }
}
```

| Ключ | Что значит |
|---|---|
| `card` | регулярное выражение начала карточки — по нему страница делится на карточки |
| `include` | карточка берётся, только если в ней есть совпадение |
| `fields.title`, `fields.published`, `fields.category` | регулярные выражения с одной группой, ищутся внутри карточки. Без `title` заголовком становится самый длинный текст ссылки на заказ |
| `details_from`, `details_to` | на странице заказа описанием считается текст между этими строками. Без них — мета-описание и начало текста страницы |
| `headers` | дополнительные заголовки запроса |

Ссылка на заказ в карточке — первая ссылка, подходящая под шаблон источника.

## Как подключить сайт через `html`

1. Откройте страницу со списком заказов и скопируйте адрес любого заказа.
2. Замените в нём изменяемую часть на регулярное выражение: `/tasks/5526433/slug.html` → `/tasks/\d+/[^/]+\.html`.
3. Сохраните источник и нажмите «Опросить». Если ссылки не нашлись, под источником появится ошибка.

Тип `html` не подходит для сайтов, которые рисуют список скриптами (SPA): в исходном HTML таких страниц ссылок нет.
Такие сайты почти всегда берут заказы из JSON API — подключите его типом `json`.

Для страниц, доступных только после входа, укажите в источнике Cookie из браузера. Сессия со временем истекает,
и Cookie придётся обновлять.

## Готовые площадки

Кнопка «Готовые площадки» заполняет форму источника одним нажатием. Список у каждой установки свой и в репозиторий
не входит: он читается из файла `config/presets.json` (переменная `PRESETS_FILE`). Формат — JSON-массив:

```json
[
  {
    "name": "Название площадки",
    "kind": "json",
    "url": "https://example.net/api/orders",
    "pattern": "",
    "interval_sec": 600,
    "note": "подсказка в списке",
    "config": { "items": "orders", "fields": { "title": "title", "url": "/orders/{id}" } }
  }
]
```

Пример для каждого типа — в [`config/presets.example.json`](../config/presets.example.json). Скопируйте его
в `config/presets.json` и замените на свои площадки. В Docker папка `config` подключается к backend только для чтения,
файл перечитывается при каждом открытии списка, перезапуск не нужен.

Проверить все площадки из файла на живых сайтах:

```bash
cd backend && PRESETS_FILE=$PWD/../config/presets.json LIVE=1 go test ./internal/sources -run Live -v
```

## Если площадку подключить не получается

- Заказы видны только после входа, а вход защищён одноразовыми токенами или капчей. Cookie здесь не поможет надолго.
- На сайте нет списка заказов, только каталог исполнителей и форма заявки.
- Сайт закрыт антиботом или не отвечает с вашего сервера.

Иногда такие площадки доступны через агрегаторы заказов с открытым JSON API — их подключают типом `json`.

## Новый тип источника

Если площадку не описать настройками, реализуйте интерфейс `Fetcher` (и при необходимости `Detailer`)
в `backend/internal/sources` и добавьте его в `Kinds` и в `New`. Тип должен оставаться универсальным:
всё, что относится к конкретному сайту, выносите в `Config`.

Опрашивайте площадки не чаще раза в несколько минут и соблюдайте их правила.
